# 统一 桌面 / 平板 / 手机 三端积分榜 UI

目前三个尺寸的积分榜确实走了三套不同的呈现逻辑，所以看起来不一致。以下是已确认的差异与修正方案。

## 现状差异（已核对代码）

1. **标题条不同**：`lg` 以上显示「细体大标题 + 视图切换 + 最新赛事日期」；`lg` 以下（含平板）改成 ESPN 实心黑底标题条。两套完全不同的视觉语言。
2. **平板处于夹缝**：`useIsMobile` 的断点是 768px，所以 768–1023px 的平板用的是桌面表格，但拿不到桌面的视图切换（总榜／最近5场／胜率榜）和赛事入口。
3. **手机忽略视图选择**：手机端直接渲染 `rankings`（总榜），不跟随 `rankingView`，即使之后在窄屏加了切换也不会生效。
4. **列宽在平板会挤**：桌面表格的固定列宽（#、场次、胜、胜率、积分）加上 `gap-5 px-5`，在 768px 宽度下留给球员名字的空间被压得很窄。
5. **手机独有的吸顶列图例**在平板／桌面没有对应元素，滚动体验不同。

## 修正方案

**一套标题，一套控件**
- 三端统一使用 ESPN 实心标题条（`SectionHeading variant="bar"`），标题为「联赛积分榜 / League Standings」，右侧 action 显示球员数。
- 标题条下方放一条统一的控制行：视图切换（总榜｜最近5场｜胜率榜）+「赛事纪录」链接 + 最新赛事日期。桌面横排一行；平板保留切换与链接、日期换行到下一行；手机切换按钮改为等宽平铺、满足 44px 触控高度，日期显示在按钮下方一行小字。
- 移除桌面专属的第二套细体标题与它旁边的控件组。

**视图逻辑统一**
- 把 `desktopRankings` 改名为按视图计算的单一 `viewRankings`，手机与桌面都用它；`RankDelta` 只在总榜显示（三端一致）。

**平板适配**
- 桌面表格加入中间断点的列宽与间距（`md` 用较窄的 stat 列与 `gap-3 px-4`，`lg` 起恢复现状），保证 768px 下球员名字仍有足够空间。
- 数字字号在 `md` 略小、`lg` 恢复，避免换行。

**滚动体验一致**
- 手机吸顶列图例保留，但在平板／桌面把表头行做成吸顶（`sticky`，偏移与 header 高度一致），三端滚动时都能看到列名。

**不改动的部分**
- 排名计算、积分逻辑、数据获取、RLS、后台功能一律不动，只调整前端呈现。

## 技术要点

- 涉及文件：`src/pages/RankingPage.tsx`（标题＋控制行＋视图数据源＋断点结构）、`src/components/DesktopRankingTable.tsx`（响应式列宽、吸顶表头）、必要时 `src/components/MobileRankingCard.tsx`（跟随视图时的主指标高亮）。
- 断点约定：手机 `<768`（`useIsMobile`）、平板 `768–1023`（`md`）、桌面 `≥1024`（`lg`）。
- 仅使用现有语义 token 与 `t.ranking.*` 文案，新增文案（视图名、最新赛事）走 zh/en 双语。
- 验证：Playwright 分别在 390 / 834 / 1440 宽度截图对比三端结构一致。
